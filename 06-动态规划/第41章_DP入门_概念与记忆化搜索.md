# 第41章 DP入门：概念与记忆化搜索

> 前面学过的算法（贪心、分治、DFS/BFS 暴搜）各有所长，但有一类问题它们都束手无策：**需要记录中间结果、避免重复计算**的问题。比如求斐波那契数列第 50 项，朴素递归会算到天荒地老；而只要把算过的值"记在小本本上"，瞬间就能出结果。这就是动态规划（Dynamic Programming, DP）的起点。DP 是 CSP-S 的绝对核心，几乎每场复赛必考，本章将从"为什么需要 DP"出发，带你建立 DP 的思维框架。

!!! info "本章内容"
    - DP 的核心思想：拆分子问题、记录答案、避免重复计算
    - DP 三要素：状态定义、状态转移方程、边界条件
    - DP 两大性质：最优子结构、无后效性
    - 记忆化搜索（自顶向下）：递归 + 备忘录
    - 递推（自底向上）：循环填表，对比两种实现
    - DP 设计四步法：定义状态 → 写转移 → 定边界 → 实现验证
    - 经典例题：数字三角形、数楼梯、采药（01 背包引子）

## 💡 生活类比

打个比方：你要从家走到学校，中间要经过若干路口，每个路口有多条岔路，你想找一条**总路程最短**的路线。

- **暴搜**：把所有可能的路线都走一遍，记录最短的。路线多了根本走不完。
- **贪心**：每到个路口就选"眼前最近"的那条。可眼前近不代表整体短，可能后面绕大远路。
- **DP**：从学校**倒着**往家算——先算"离学校 1 个路口的所有点，到学校的最短距离"；再算"离学校 2 个路口的点，到学校的最短距离 = 当前边 + 下一站已算好的最短距离"……一层层往家推。每个点只算一次，算过的结果记下来，绝不重复算。

这就是 DP 的精髓：**把大问题拆成小问题，小问题的答案记下来，组合成大问题的答案**。

## 第1节 DP核心思想

### 1.1 为什么要学DP

先看一个"反面教材"——朴素递归求斐波那契数列：

```cpp
#include <bits/stdc++.h>
using namespace std;
// 朴素递归：大量重复计算
long long fib(int n) {
    if (n <= 2) return 1;
    return fib(n - 1) + fib(n - 2);
}
int main() {
    int n; cin >> n;
    cout << fib(n) << endl;
    return 0;
}
```

`fib(40)` 在普通电脑上要跑好几秒，`fib(50)` 基本跑不动。为什么？看调用树：

```
                fib(5)
              /        \
          fib(4)       fib(3)      ← fib(3) 算了 2 次！
         /     \       /    \
     fib(3)  fib(2)  fib(2) fib(1)  ← fib(2) 算了 3 次！
     /   \
  fib(2) fib(1)
```

`fib(3)` 被算了 2 次，`fib(2)` 被算了 3 次。n 越大，重复越恐怖——时间复杂度是 $O(2^n)$，指数级爆炸。

!!! tip "DP的诞生"
    如果我们把每个 `fib(k)` 第一次算出来后**存进数组**，下次再要就直接查表，不就省了？这正是 DP 的核心——**用空间换时间，记录子问题答案避免重复计算**。

### 1.2 DP vs 分治 vs 贪心

| 算法 | 核心思路 | 子问题关系 | 是否记录中间结果 | 典型场景 |
|------|---------|-----------|----------------|---------|
| **分治** | 大问题拆成互不重叠的子问题 | 子问题**独立** | 否（不需要） | 归并排序、快速幂 |
| **贪心** | 每步选当前最优 | 不回看、不记录 | 否 | 区间调度、Huffman |
| **DP** | 大问题拆成**重叠**子问题 | 子问题**重叠且依赖** | **是（核心）** | 数字三角形、背包、LIS |

!!! warning "贪心为什么不能替代DP"
    贪心只看眼前最优，不保证全局最优。例如数字三角形，贪心会"每层选较大的儿子往下走"，但这条路径未必全局最大——可能这一步小一点，但后面两条岔路都很大。DP 会**把所有子问题的最优都算出来再比较**，保证全局最优。

## 第2节 DP三要素

!!! info "DP三要素"
    - **状态定义**：用变量（如下标）描述一个子问题
    - **状态转移方程**：大问题如何由小问题推出
    - **边界条件（初始值）**：最小子问题的答案，递推的起点

### 2.1 用"阶段+决策+状态"理解DP

任何 DP 都可以从三个视角拆解：

| 视角 | 含义 | 数字三角形中的体现 |
|------|------|------------------|
| **阶段** | 问题推进的"层"，按某种顺序展开 | 三角形的第 i 行（从底向上） |
| **状态** | 该阶段下所有可能情况的描述 | `f[i][j]`：从 (i,j) 走到底的最大和 |
| **决策** | 每个状态下可选的动作及其代价 | 向左下走 或 向右下走 |

### 2.2 以斐波那契为例

- **状态**：`f[i]` 表示第 i 个斐波那契数
- **转移**：`f[i] = f[i-1] + f[i-2]`
- **边界**：`f[1] = f[2] = 1`

三行就把问题说清楚了。这就是 DP 的"建模"过程——**把问题翻译成状态和转移**。

## 第3节 DP两大性质

DP 不是万能的，一个问题能用 DP 求解，必须满足两个性质。

### 3.1 最优子结构

!!! info "最优子结构"
    **子问题的最优解能构成整体最优解**。即大问题的最优值，可以由若干小问题的最优值组合得到。

数字三角形中：`f[i][j]`（从 (i,j) 到底的最优）= `a[i][j] + max(f[i+1][j], f[i+1][j+1])`。子问题 `f[i+1][j]` 和 `f[i+1][j+1]` 都取最优时，整体才最优。

反例：求"最长的简单路径"（每个点只走一次）通常**没有**最优子结构——子问题"从 A 到终点的最长路"可能已经用过某些点，影响主问题的可选集合。

### 3.2 无后效性

!!! info "无后效性"
    **未来只看当前状态，不看历史路径**。即一旦确定了当前状态，后面的演化只依赖这个状态的值，与"怎么到达这个状态"无关。

数字三角形满足无后效性：`f[i][j]` 一旦确定，从 (i,j) 继续往下走的最优值与"之前怎么走到 (i,j)"无关。

!!! warning "破坏无后效性的典型情况"
    如果状态里**含历史信息**（如"已经走过的路径""当前剩余哪些物品"），就破坏了无后效性。例如：
    
    - 求"经过所有点恰好一次的最短路径"（TSP）：状态必须包含"已访问集合"，这就需要状压 DP
    - 求最长简单路径：状态需记录"走过的点"，通常 NP-hard，DP 难以高效处理

### 3.3 两大性质速查表

| 性质 | 一句话理解 | 不满足时的后果 |
|------|-----------|--------------|
| 最优子结构 | 子最优可拼成整体最优 | 无法写出转移方程 |
| 无后效性 | 未来只看当前状态 | 状态需扩维，复杂度爆炸 |

## 第4节 记忆化搜索（自顶向下）

### 4.1 从暴搜到记忆化

记忆化搜索 = **递归 + 备忘录**。思路：递归写法天然符合"大问题拆小问题"的思维方式，但朴素递归会重复计算；加一个数组"记一下算过的值"，下次直接返回。

以斐波那契为例，三步演进：

```cpp
// ① 暴搜：O(2^n)，n=50 跑不动
long long fib(int n) {
    if (n <= 2) return 1;
    return fib(n - 1) + fib(n - 2);
}

// ② 记忆化：O(n)，n=50 瞬间出结果
long long memo[100];
long long fib(int n) {
    if (n <= 2) return 1;
    if (memo[n] != 0) return memo[n];  // 算过直接返回
    return memo[n] = fib(n - 1) + fib(n - 2);
}
```

### 4.2 记忆化搜索通用框架

```cpp
#include <bits/stdc++.h>
using namespace std;

// memo[] 初始化为"未计算"标记（通常是 -1）
// 递归函数：先查备忘录，没算过才递归并写入
int solve(参数) {
    if (边界条件) return 初始值;
    if (memo[状态] != -1) return memo[状态];   // 已计算，直接返回
    int res = ...;                             // 用 solve(更小的子问题) 组合
    return memo[状态] = res;                   // 记录并返回
}
```

!!! tip "备忘录为什么初始化为-1"
    因为很多 DP 的答案可能是 0（如"最大价值"不选时为 0）。如果用 0 当"未计算"标记，会误判已算过。**用 -1（或一个不可能出现的值）当"未计算"标记最稳妥**。

### 4.3 记忆化搜索的优缺点

| 优点 | 缺点 |
|------|------|
| 符合自然思维，**易想易写** | 递归有**栈开销**，常数略大 |
| 只算"用得到"的状态，天然剪枝 | 递归深度大时可能**栈溢出** |
| 状态转移顺序由递归自动处理 | 难以做滚动数组等空间优化 |

## 第5节 递推（自底向上）

### 5.1 递推的思路

递推 = **循环填表**。从最小子问题（边界）开始，按确定顺序逐个填表，直到目标状态。不需要递归，没有栈开销。

斐波那契的递推写法：

```cpp
#include <bits/stdc++.h>
using namespace std;
long long f[100];
int main() {
    int n; cin >> n;
    f[1] = f[2] = 1;                 // 边界
    for (int i = 3; i <= n; i++)     // 从小到大填表
        f[i] = f[i-1] + f[i-2];
    cout << f[n] << endl;
    return 0;
}
```

### 5.2 记忆化搜索 vs 递推

| 维度 | 记忆化搜索（自顶向下） | 递推（自底向上） |
|------|---------------------|----------------|
| 思维方向 | 从大问题向小问题递归 | 从小问题向大问题迭代 |
| 实现方式 | 递归 + 备忘录 | 循环填表 |
| 计算顺序 | 由递归调用自动决定 | 需手动确定（关键！） |
| 常数效率 | 略低（递归开销） | 较高 |
| 易想程度 | ✅ 易想（符合直觉） | 需想清计算顺序 |
| 空间优化 | 难（递归依赖全部状态） | ✅ 易做滚动数组优化 |
| 栈溢出风险 | 有（n 大时） | 无 |

!!! tip "何时用记忆化，何时用递推"
    - **初学/比赛想题阶段**：先用记忆化搜索把思路跑通（易想、不易错）
    - **优化阶段**：转成递推，并考虑滚动数组降空间
    - **数据规模极大**（如 n=10⁷）：必须递推，避免栈溢出
    - **状态依赖关系复杂**（如树形 DP、区间 DP）：记忆化更直观

## 第6节 DP设计四步法

!!! info "DP设计四步法"
    1. **定义状态含义**：`f[...]` 表示什么？
    2. **写状态转移方程**：`f[...]` 由哪些更小的状态推出？
    3. **确定边界条件和计算顺序**：最小子问题的值；状态之间谁先算？
    4. **实现并验证**：写代码，用小数据手算核对

### 6.1 四步法完整演示：数字三角形

**题目**（P1216）：给定一个数字三角形，从顶向下走，每次可走到下方或右下方相邻位置，求路径最大和。

```
        7
       3 8
      8 1 0
     2 7 4 4
    4 5 2 6 5
```

**第①步：定义状态**

`f[i][j]`：从第 i 行第 j 列的数字出发，走到**底行**的路径最大和。

**第②步：写转移方程**

从 `(i,j)` 出发，可以走到 `(i+1,j)` 或 `(i+1,j+1)`：

$$f[i][j] = a[i][j] + \max(f[i+1][j],\ f[i+1][j+1])$$

**第③步：边界与计算顺序**

- 边界：底行 `f[n][j] = a[n][j]`（已经在底部，无需再走）
- 顺序：从**底行向上**逐行计算（保证算 `f[i][j]` 时 `f[i+1][...]` 已算好）

**第④步：实现验证**

手算第 5 行往上：
```
第5行: f[5][*]=4 5 2 6 5  (边界)
第4行: f[4][1]=2+max(4,5)=7; f[4][2]=7+max(5,2)=12; ...
第3行: f[3][1]=8+max(7,12)=20; ...
第2行: f[2][1]=3+max(20,12)=23; f[2][2]=8+max(12,11)=20
第1行: f[1][1]=7+max(23,20)=30  ← 答案
```

### 6.2 记忆化搜索写法

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAXN = 1005;
int a[MAXN][MAXN], f[MAXN][MAXN];
int n;

// f[i][j]：从(i,j)走到底的最大和
int dfs(int i, int j) {
    if (i == n) return a[i][j];            // 边界：到底行
    if (f[i][j] != -1) return f[i][j];    // 已算过，直接返回
    return f[i][j] = a[i][j] + max(dfs(i+1, j), dfs(i+1, j+1));
}

int main() {
    scanf("%d", &n);
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= i; j++)
            scanf("%d", &a[i][j]);
    memset(f, -1, sizeof(f));              // 初始化为"未计算"
    printf("%d\n", dfs(1, 1));
    return 0;
}
```

### 6.3 递推写法（对比）

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAXN = 1005;
int a[MAXN][MAXN], f[MAXN][MAXN];
int n;

int main() {
    scanf("%d", &n);
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= i; j++)
            scanf("%d", &a[i][j]);
    // 边界：底行
    for (int j = 1; j <= n; j++) f[n][j] = a[n][j];
    // 从底向上递推
    for (int i = n - 1; i >= 1; i--)
        for (int j = 1; j <= i; j++)
            f[i][j] = a[i][j] + max(f[i+1][j], f[i+1][j+1]);
    printf("%d\n", f[1][1]);
    return 0;
}
```

两种写法结果相同，递推更高效（无递归开销，可用滚动数组优化空间）。

!!! tip "自顶向下走 vs 自底向上推"
    数字三角形两种思路都常见：
    - **自顶向下走**：`f[i][j]` 表示从顶到 `(i,j)` 的最大和，向下递推
    - **自底向上推**：`f[i][j]` 表示从 `(i,j)` 走到底的最大和，向上递推
    
    后者**边界统一**（底行就是 `a[n][j]`），代码更简洁，是更推荐的写法。

## 第7节 常见误区

### 误区1：状态定义不清

!!! warning "问题"
    初学者常把 `f[i]` 含义写得含糊，导致转移时不知道该用什么。例如"最长上升子序列"，若 `f[i]` 定义为"前 i 个数的 LIS 长度"就**无法转移**——因为你不知道第 i 个数是否被选。

    **正确定义**：`f[i]` 表示**以 a[i] 结尾**的 LIS 长度。这样 `f[i] = max(f[j]+1)`，其中 `j<i` 且 `a[j]<a[i]`。状态必须"唯一确定"才能转移。

### 误区2：边界条件漏写或写错

!!! warning "问题"
    - 数字三角形：忘记初始化底行 `f[n][j] = a[n][j]`，导致递推全是 0
    - 斐波那契：忘记 `f[1]=f[2]=1`，递推结果全错
    - 记忆化搜索：忘记处理 `n<=2` 直接返回，导致访问越界
    
    **检查清单**：写完 DP 后，先确认"最小的、不能再拆的子问题"答案是否正确。

### 误区3：记忆化数组没初始化为-1

!!! warning "问题"
    全局数组默认全 0，若答案可能为 0（如"不选任何物品，价值为 0"），用 0 当"未计算"标记会**误判已算过**，直接返回 0 而不递归，导致结果错误。

    ```cpp
    // ❌ 错误：用 0 当标记，答案为 0 时会误判
    if (f[i][j] != 0) return f[i][j];
    
    // ✅ 正确：用 -1 当标记，memset 初始化
    memset(f, -1, sizeof(f));
    if (f[i][j] != -1) return f[i][j];
    ```

### 误区4：无后效性被破坏

!!! warning "问题"
    状态设计时如果**隐含了历史信息**，会破坏无后效性，导致转移出错。

    例如"求从起点到终点的最长**简单**路径（不能重复走）"：如果状态只记"当前在哪个点"，无法体现"哪些点已走过"。必须把"已访问集合"也放进状态（状压 DP），否则转移会重复访问。

    **判断方法**：检查"到达当前状态的不同路径，是否会影响后续决策"。若会，说明状态信息不足，需扩维。

### 误区5：递归深度过大栈溢出

!!! warning "问题"
    记忆化搜索用递归实现，当递归深度达 $10^5$ 级别（如链状结构），默认栈空间（Windows 约 1MB）会**栈溢出 RE**。

    **解决方案**：
    1. 编译时开大栈：`#pragma comment(linker, "/STACK:256000000")`（MSVC）或 `-Wl,--stack=268435456`（MinGW）
    2. 改用递推（推荐）：把递归转成循环填表
    3. 手写栈模拟递归

## 第8节 配套习题精讲

### 习题1：[P1216] 数字三角形 [IOI1994]

**题意**：给定一个数字三角形（n≤1000，每个数字≤100），从顶部出发，每步可走到正下方或右下方相邻位置，求从顶到底的路径最大和。

**思路**：DP 入门经典，用第6节四步法。

- 状态：`f[i][j]` 表示从 `(i,j)` 走到底的最大和
- 转移：`f[i][j] = a[i][j] + max(f[i+1][j], f[i+1][j+1])`
- 边界：`f[n][j] = a[n][j]`
- 顺序：自底向上

**完整AC代码（递推 + 滚动数组优化空间）**：

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAXN = 1005;
int a[MAXN][MAXN];
int f[MAXN];        // 滚动数组，只存一行
int n;

int main() {
    scanf("%d", &n);
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= i; j++)
            scanf("%d", &a[i][j]);
    // 初始化底行
    for (int j = 1; j <= n; j++) f[j] = a[n][j];
    // 从倒数第二行向上递推
    for (int i = n - 1; i >= 1; i--)
        for (int j = 1; j <= i; j++)
            f[j] = a[i][j] + max(f[j], f[j+1]);
    printf("%d\n", f[1]);
    return 0;
}
```

**复杂度**：时间 $O(n^2)$，空间 $O(n)$（滚动数组）。

### 习题2：[P1255] 数楼梯

**题意**：有 n 级台阶（n≤5000），每次可以走 1 级或 2 级，求从第 0 级走到第 n 级共有多少种走法。

**思路**：斐波那契变形。

- 状态：`f[i]` 表示走到第 i 级的走法数
- 转移：`f[i] = f[i-1] + f[i-2]`（最后一步走 1 级或 2 级）
- 边界：`f[0] = 1`（在原地算 1 种），`f[1] = 1`

!!! warning "高精度问题"
    n=5000 时，`f[5000]` 是一个 1000 多位的大数，`long long` 根本装不下。必须用**高精度加法**。这里演示记忆化搜索 + 高精度。

**完整AC代码（高精度 + 递推）**：

```cpp
#include <bits/stdc++.h>
using namespace std;

// 高精度大整数，用 vector<int> 存储每一位（逆序，低位在前）
struct BigInt {
    vector<int> d;
    BigInt() {}
    BigInt(int x) { while (x) { d.push_back(x % 10); x /= 10; } }
};

// 高精度加法
BigInt add(const BigInt &a, const BigInt &b) {
    BigInt c;
    int carry = 0, n = max(a.d.size(), b.d.size());
    for (int i = 0; i < n || carry; i++) {
        int sum = carry;
        if (i < a.d.size()) sum += a.d[i];
        if (i < b.d.size()) sum += b.d[i];
        c.d.push_back(sum % 10);
        carry = sum / 10;
    }
    return c;
}

void print(const BigInt &x) {
    if (x.d.empty()) { printf("0"); return; }
    for (int i = x.d.size() - 1; i >= 0; i--) printf("%d", x.d[i]);
}

int main() {
    int n;
    scanf("%d", &n);
    if (n == 0) { printf("1\n"); return 0; }
    if (n == 1) { printf("1\n"); return 0; }
    vector<BigInt> f(n + 1);
    f[0] = BigInt(1);   // 边界：原地 1 种
    f[1] = BigInt(1);   // 边界：走 1 级 1 种
    for (int i = 2; i <= n; i++)
        f[i] = add(f[i-1], f[i-2]);   // 递推
    print(f[n]);
    printf("\n");
    return 0;
}
```

**复杂度**：时间 $O(n \cdot L)$，L 为大数位数（约 $n/5$）；空间 $O(n \cdot L)$。可用滚动数组优化为 $O(L)$。

!!! tip "记忆化搜索写法对比"
    若用记忆化搜索，只需把 `f[i] = add(f[i-1], f[i-2])` 改成递归函数，加 `memo[]` 标记。但本题递推更直观，且无栈溢出风险。

### 习题3：[P1048] 采药 [NOIP2005]

**题意**：有 T 分钟采药时间（T≤1000），n 株草药（n≤100），每株有采摘时间 `t[i]` 和价值 `v[i]`。在限定时间内采药，使总价值最大。

**思路**：这是 **0/1 背包**的简化版，作为 DP 四步法的综合训练，也为下一章背包 DP 做铺垫。

- 状态：`f[j]` 表示时间不超过 j 时能采到的最大价值
- 转移：`f[j] = max(f[j], f[j-t[i]] + v[i])`（倒序遍历 j）
- 边界：`f[j] = 0`（一开始什么都没采）
- 顺序：每株草药"选或不选"，j 必须**倒序**（保证每株只选一次）

**为什么倒序？** 因为 `f[j-t[i]]` 必须用"还没考虑当前草药"的旧值，正序会让同一株被多次选取（变成完全背包）。

**完整AC代码（一维 0/1 背包）**：

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAXT = 1005;
int t[105], v[105];
int f[MAXT];   // f[j]: 时间不超过 j 的最大价值

int main() {
    int T, n;
    scanf("%d %d", &T, &n);
    for (int i = 1; i <= n; i++) scanf("%d %d", &t[i], &v[i]);
    // 0/1 背包：每株草药选或不选
    for (int i = 1; i <= n; i++)
        for (int j = T; j >= t[i]; j--)       // j 倒序！防重复
            f[j] = max(f[j], f[j - t[i]] + v[i]);
    printf("%d\n", f[T]);
    return 0;
}
```

**复杂度**：时间 $O(nT)$，空间 $O(T)$。

## 📖 本章总结

### 思维导图

- DP入门
  - 核心思想
    - 拆子问题、避免重复
    - 记录答案、空间换时间
  - 三要素
    - 状态定义：用下标描述子问题
    - 转移方程：大问题由小问题推出
    - 边界条件：递推的起点
  - 两大性质
    - 最优子结构：子最优 → 整体最优
    - 无后效性：未来只看当前状态，不看历史
  - 实现方式
    - 记忆化搜索：自顶向下，递归 + 备忘录，易想难优化
    - 递推：自底向上，循环填表，高效常优化

### 核心口诀

| 口诀 | 含义 |
|------|------|
| **大拆小、记答案、不重算** | DP 核心：子问题 + 记忆化 |
| **状态清楚、转移明白、边界不忘** | DP 三要素缺一不可 |
| **子最优拼成整体最优** | 最优子结构的直观理解 |
| **未来只看当前，不看历史** | 无后效性的判断标准 |
| **备忘录初始化 -1** | 避免与合法答案 0 冲突 |
| **记忆化易想、递推高效** | 两种写法各有侧重 |
