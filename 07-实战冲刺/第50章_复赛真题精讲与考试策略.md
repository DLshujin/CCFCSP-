## 💡 生活类比

打个比方，CSP-S 复赛就像是一场**四道菜的中式宴席厨师比赛**。你有四个小时，要做四道菜：第一道是凉菜（T1 签到），手快有手慢无；第二道是热炒（T2 基础），考验基本功；第三道是红烧（T3 较难），需要慢工出细活；第四道是佛跳墙（T4 压轴），绝大多数选手只能做出半成品。

聪明的厨师不会一上来就死磕佛跳墙——他会先把凉菜和热炒稳稳端上桌，保证基础分拿到手，再用剩余时间挑战红烧和佛跳墙。即便后两道菜只做出半成品，评委也会给"色香味部分分"。这就是复赛的核心策略：**先拿能拿的分，再冲能冲的题**。

再打个比方，考场上的调试就像医生看病——你不能只看症状（程序报错）就瞎开药，得先量体温（打印中间变量）、做化验（对拍验证）、定位病灶（断言检查），然后才能对症下药。盲目改代码只会越改越乱。

## 核心概念

### 50.1 CSP-S 复赛题型分析

CSP-S 复赛共 4 道题，每题 100 分，总分 400 分，限时 4 小时（14:30~18:30）。四道题难度递增，以下是各题的详细分析：

| 题号 | 定位 | 难度 | 建议用时 | 目标分数 | 常见算法类型 |
|------|------|------|----------|----------|-------------|
| T1 | 签到题 | ★~★★ | 30~60 分钟 | 100 分 | 模拟、贪心、枚举、BFS/DFS |
| T2 | 基础题 | ★★~★★★ | 60~90 分钟 | 70~100 分 | DP、图论、二分、数据结构 |
| T3 | 较难题 | ★★★~★★★★ | 60~90 分钟 | 30~80 分 | 高级 DP、高级图论、数学 |
| T4 | 压轴题 | ★★★★~★★★★★ | 60~90 分钟 | 10~50 分 | 综合算法、高级数据结构 |

!!! tip "分数预期参考"
    - 一等奖线通常在 200~250 分左右（因省份而异）
    - 稳拿 T1 满分（100）+ T2 大部分分（70~100）= 170~200 分，已接近一等奖线
    - T3 拿 30~50 分暴力分即可拉开差距
    - T4 拿到 10~20 分就是 bonus，不必强求

#### 各题详细特征

**T1 签到题**：通常考查基础算法或模拟，思维难度低但可能有小陷阱。常见题型包括：暴力枚举、BFS 最短路、简单贪心、差分/前缀和。关键在于**快速 AC**，不要在此题耗费超过 1 小时。

**T2 基础题**：通常是标准算法的直接应用或轻微变形。常见题型包括：动态规划（背包、区间 DP、树形 DP）、图论（最短路、最小生成树、拓扑排序）、二分答案。关键在于**识别算法模型并正确实现**。

**T3 较难题**：算法难度显著提升，可能需要多个算法组合或巧妙的转化。常见题型包括：高级 DP（状压、数位）、高级图论（Tarjan、网络流）、数学（组合、数论）。策略是**先拿暴力分再优化**。

**T4 压轴题**：通常是难题或综合题，区分度极大。常见题型包括：数据结构（线段树、LCT）、高级 DP 优化、构造题、交互题。策略是**拿部分分为主**，除非有充分时间否则不追求 AC。

### 50.2 暴力分策略与部分分技巧

!!! warning "暴力分是复赛的生命线"
    在 CSP-S 复赛中，一个完全不会做的选手如果能拿满每道题的暴力分（通常每题 20~40 分），总分就能达到 80~160 分，这在很多省份已经足以获奖。**暴力分不是"放弃"，而是"保底"**。

#### 暴力分的五大来源

| 暴力分类型 | 典型分值 | 实现方式 | 适用场景 |
|-----------|---------|---------|---------|
| 小数据暴力 | 20~30 分 | 枚举/DFS/暴力搜索 | n ≤ 20 的小范围数据 |
| 特殊性质 | 10~20 分 | 针对链/树/完全图等特殊结构 | 图论题、树论题 |
| 随机数据 | 10 分 | 简单贪心/启发式 | 数据随机生成的题目 |
| 部分算法 | 20~40 分 | 正解的一部分（如只处理简单情况） | 复杂题目的简化版本 |
| 输出格式分 | 5~10 分 | 输出 -1 / 0 / 任意合法解 | 构造题、答案判定题 |

#### 高效写暴力的技巧

1. **读题后立即写暴力**：哪怕还没想到正解，先写一个 O(n²) 或 O(2^n) 的暴力程序，锁定基础分。
2. **特殊条件分支**：在代码中加 `if` 判断特殊数据范围，对不同范围用不同算法。
3. **答案输出兜底**：不确定答案时，输出一个可能的合法解（如全 0、全 1、-1），可能骗到格式分。
4. **暴力与正解共存**：在代码中保留暴力作为对拍参考。

```cpp
// 暴力分通用模板
#include <bits/stdc++.h>
using namespace std;

int n;
int a[100005];

// 暴力函数：针对小数据
int brute_force() {
    int ans = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] > a[j]) ans++;
    return ans;
}

// 正解函数：针对大数据
long long solve() {
    // 归并排序求逆序对
    // ... 正解代码 ...
    return 0;
}

int main() {
    freopen("data.in", "r", stdin);
    freopen("data.out", "w", stdout);
    cin >> n;
    for (int i = 0; i < n; i++) cin >> a[i];

    if (n <= 5000) {
        cout << brute_force() << endl;  // 小数据用暴力
    } else {
        cout << solve() << endl;         // 大数据用正解
    }
    return 0;
}
```

### 50.3 时间分配策略

#### 四小时时间分配表

| 时间段 | 任务 | 累计用时 |
|--------|------|---------|
| 14:30~14:40 | 通读四道题，标注难度与算法类型 | 10 分钟 |
| 14:40~15:30 | 做 T1（签到题），确保 AC | 1 小时 |
| 15:30~16:30 | 做 T2（基础题），优先 AC，不会则拿暴力分 | 2 小时 |
| 16:30~17:00 | 通读 T3、T4，先写暴力分 | 2.5 小时 |
| 17:00~17:45 | 攻克 T3 正解或部分分 | 3.25 小时 |
| 17:45~18:15 | 攻克 T4 部分分，或回头检查 T1/T2 | 3.75 小时 |
| 18:15~18:30 | 检查文件读写、数组大小、long long | 4 小时 |

!!! warning "时间分配三大禁忌"
    1. **禁忌一**：在 T1 上耗时超过 1 小时。T1 是签到题，如果 1 小时内没 AC，先写暴力分跳过。
    2. **禁忌二**：死磕一道题。如果一道题卡了 30 分钟毫无进展，立刻切换到下一道题。
    3. **禁忌三**：最后不检查。每年都有选手因忘开 `long long` 或数组越界丢分。

#### 读题策略

1. **至少读两遍**：第一遍快速浏览题意，第二遍仔细阅读数据范围和特殊条件。
2. **手推样例**：用样例数据手动模拟一遍，确保完全理解题意。
3. **标注关键信息**：在读题时圈出数据范围、特殊性质、输出格式。
4. **注意隐藏条件**：如"无重边""保证连通""答案不超过 10^18"等。

### 50.4 调试技巧与代码风格规范

#### 调试三件套：freopen + 断言 + 中间变量

```cpp
#include <bits/stdc++.h>
using namespace std;

// DEBUG 宏：调试时输出中间变量，提交时关闭
#define DEBUG
#ifdef DEBUG
#define dbg(x) cerr << #x << " = " << x << endl
#else
#define dbg(x)
#endif

int main() {
    // 文件重定向：CSP-S 必须写
    freopen("data.in", "r", stdin);
    freopen("data.out", "w", stdout);

    int n;
    cin >> n;
    dbg(n);  // 调试输出到 stderr，不影响 stdout

    // 断言：检查关键条件
    assert(n >= 1 && n <= 100000);

    // ... 主逻辑 ...
    return 0;
}
```

#### 代码风格检查清单

| 检查项 | 说明 | 常见错误 |
|--------|------|---------|
| `long long` | 结果可能超过 2×10^9 时必须用 | `int` 溢出，只过小数据 |
| 数组大小 | 开到数据范围 + 5 的最小 2 的幂 | RE（数组越界） |
| 初始化 | 全局变量默认 0，局部变量需手动初始化 | 局部数组残留垃圾值 |
| 文件读写 | `freopen` 文件名必须与题目要求完全一致 | 文件名拼错，0 分 |
| 取模 | 涉及大数运算记得取模 | 忘记取模或取模位置错误 |
| 边界处理 | n=0, n=1 等边界情况单独处理 | 边界数据 WA |

#### 终端命令实战

复赛中你最常用的命令流程：

```bash
# 1. 查看题目下发文件
ls                              # 输出：data.in  data.ans  sol.cpp ...

# 2. 编写代码（用任意编辑器）
vim sol.cpp                     # 或用 GUI 编辑器

# 3. 编译（必须加 -O2 -std=c++14 与评测环境一致）
g++ -o sol sol.cpp -O2 -std=c++14 -Wall

# 4. 运行测试
./sol < data.in                 # 手动看输出
./sol < data.in > my.out        # 输出重定向到文件

# 5. 对拍验证
diff my.out data.ans            # 无输出=答案一致
```

**g++ 常用参数速查**：

| 参数 | 功能 | 示例 |
|------|------|------|
| `-o <name>` | 指定输出文件名 | `g++ -o sol sol.cpp` |
| `-O2` | 开启 2 级优化（评测默认） | `g++ -O2 sol.cpp` |
| `-std=c++14` | 指定 C++14 标准 | `g++ -std=c++14 sol.cpp` |
| `-Wall` | 显示所有警告 | 帮助发现潜在 bug |
| `-g` | 生成调试信息 | 配合 GDB 使用 |
| `-DLOCAL` | 定义宏 `LOCAL` | 本地调试条件编译 |

> ⚠️ 警告：本地用 Dev-C++ 编译通过的代码，在 NOI Linux 上可能有细微差异（如 `__int128` 非标准、`stoi` 异常行为不同）。考前务必在 Linux 环境下测试一次。

#### 条件编译模板

#### 对拍四件套

复赛拿分的核心保障——**对拍**，在 Linux 下用 shell 脚本实现：

```bash
#!/bin/bash
# 对拍脚本 duipai.sh
# 用法：bash duipai.sh

g++ -o sol sol.cpp -O2 -std=c++14
g++ -o brute brute.cpp -O2 -std=c++14
g++ -o gen gen.cpp -O2 -std=c++14

for ((i=1; ; i++)); do
    ./gen > data.in          # 生成随机数据
    ./sol < data.in > sol.out
    ./brute < data.in > brute.out
    if diff sol.out brute.out > /dev/null; then
        echo "Test $i: AC"
    else
        echo "Test $i: WA!"
        echo "--- Input ---"
        cat data.in
        echo "--- Sol Output ---"
        cat sol.out
        echo "--- Brute Output ---"
        cat brute.out
        break
    fi
done
```

> 💡 生活类比
> 对拍就像"考试做完题后用计算器验算一遍"——你的正解（sol）是手算过程，暴力程序（brute）是计算器，生成器（gen）是出题人。三者配合，99% 的 bug 无处遁形。

> 📌 要点：
> - CSP-S 复赛环境为 NOI Linux，必须用 `g++` 编译
> - 标准编译命令：`g++ -o sol sol.cpp -O2 -std=c++14 -Wall`
> - 条件编译 `-DLOCAL` 实现本地/提交无缝切换
> - 对拍四件套（gen + brute + sol + duipai.sh）是保分利器

## 代码实现

### 对拍模板

对拍是验证代码正确性的核心手段，由四个文件组成：

**1. 数据生成器 `gen.cpp`**：

```cpp
#include <bits/stdc++.h>
using namespace std;
int main() {
    // 使用当前时间作为随机种子
    srand(time(0));
    int n = rand() % 20 + 1;        // 随机生成 1~20 的 n
    cout << n << endl;
    for (int i = 0; i < n; i++)
        cout << rand() % 100 << " "; // 随机生成 0~99 的数
    cout << endl;
    return 0;
}
```

**2. 暴力程序 `brute.cpp`**：

```cpp
#include <bits/stdc++.h>
using namespace std;
int n, a[25];
int main() {
    cin >> n;
    for (int i = 0; i < n; i++) cin >> a[i];
    // 暴力 O(n^2)
    int ans = 0;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] > a[j]) ans++;
    cout << ans << endl;
    return 0;
}
```

**3. 正解程序 `sol.cpp`**：你的 AC 代码。

**4. 对拍脚本 `duipai.bat`**（Windows）：

```bat
@echo off
:loop
    gen.exe > data.txt
    brute.exe < data.txt > ans1.txt
    sol.exe < data.txt > ans2.txt
    fc ans1.txt ans2.txt > nul
    if errorlevel 1 (
        echo === WA! ===
        type data.txt
        echo --- brute --- 
        type ans1.txt
        echo --- sol ---
        type ans2.txt
        pause
    ) else (
        echo AC
    )
goto loop
```

!!! tip "对拍效率技巧"
    1. 暴力程序一定要**简单到不可能错**。
    2. 数据范围从小开始（n ≤ 10），逐步增大。
    3. 对拍发现 WA 后，保存 `data.txt` 中的数据用于调试。
    4. 考场上如果来不及写对拍，至少手造几组边界数据测试。

## ⚠️ 常见误区

### 误区1：忘开 `long long` 导致溢出

**错误**：结果可能超过 `INT_MAX`（约 2.1×10^9），但全程使用 `int`。

**后果**：小数据 AC，大数据 WA 或 RE，丢失 60~70 分。

**修复**：凡涉及乘法、累加、大数运算，一律使用 `long long`。数组下标用 `int`，数值用 `long long`。

```cpp
// 错误
int ans = 0;
ans += 1LL * a[i] * b[j];  // a[i]*b[j] 仍可能溢出

// 正确
long long ans = 0;
ans += 1LL * a[i] * b[j];   // 显式转 long long
```

### 误区2：数组大小开错导致 RE

**错误**：数组开得刚好等于数据范围上限，没有留余量。

**后果**：访问 `a[n]` 时越界，Runtime Error，该测试点 0 分。

**修复**：数组大小开到 `MAXN = 数据范围 + 10`，宁可多开不可少开。

```cpp
const int MAXN = 100005;  // 数据范围 10^5，开到 100005
int a[MAXN];              // 全局数组，自动初始化为 0
```

### 误区3：时间分配失衡，死磕一题

**错误**：在 T2 上花了 2 小时仍未 AC，导致 T3、T4 完全没看。

**后果**：T2 可能只差一个小 bug，但 T3、T4 的暴力分（30~60 分）白白丢失。

**修复**：严格遵守时间分配表，单题超时 30 分钟无进展立即切换。先确保每道题都有暴力分，再回头攻克难题。

### 误区4：忘记 `freopen` 或文件名拼错

**错误**：代码逻辑完全正确，但忘了写 `freopen`，或文件名多了一个字母。

**后果**：程序从键盘读取输入，所有测试点全部超时或 WA，直接 0 分。

**修复**：写代码的第一步就写好 `freopen`，写完后再次检查文件名。考试结束前 15 分钟再检查一遍。

```cpp
// 第一行就写 freopen，养成习惯
freopen("airport.in", "r", stdin);
freopen("airport.out", "w", stdout);
```

### 误区5：不对拍，盲目提交

**错误**：写完代码直接交，没有用样例测试或对拍验证。

**后果**：小 bug 导致大量丢分，而这些问题本可以通过简单测试发现。

**修复**：每道题写完后，至少做三件事：
1. 用题目给出的样例测试
2. 手造边界数据（n=1, n=2, 全相同、全不同）
3. 有时间则对拍

### 例题1：[CSP-S 2021 T1] 廊桥分配

**题意概括**：机场有 n 个廊桥，需分配给国内（m1 个航班）和国际（m2 个航班）两个区域。每个航班有到达和离开时间，到达时优先选择编号最小的空闲廊桥停靠；若无空闲廊桥则停远机位。求如何分配 n 个廊桥使停在廊桥的航班总数最多。

**数据范围**：n ≤ 100000，m1, m2 ≤ 100000。

**数据范围与部分分分析**：

| 数据范围 | 对应算法 | 预期分数 |
|---------|---------|---------|
| n, m ≤ 20 | 暴力枚举分配方案 + 模拟 | 20 分 |
| n, m ≤ 5000 | O(m²) 暴力模拟 | 50 分 |
| n, m ≤ 10^5 | 优先队列 + 前缀和 | 100 分 |

**算法选择**：

**思路一（暴力）**：枚举国内分配 i 个廊桥、国际分配 n-i 个。对每个方案，O(m) 模拟航班停靠过程。总复杂度 O(n × m)，可得 50 分。

**思路二（正解）**：关键观察——以"无限廊桥"模拟，每个航班会被分配到一个编号最小的廊桥。若分配 k 个廊桥，恰好有被分配到 1~k 号廊桥的航班被服务。因此预处理 `g[k]` = 前 k 个廊桥服务的航班数（前缀和），再枚举分配方案取最大值。

**AC 代码**：

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 100005;
int n, m1, m2;
int g1[MAXN], g2[MAXN];  // g[k] = 前 k 个廊桥服务的航班数

// 模拟航班停靠，预处理 g[] 数组
void solve(int m, int g[]) {
    vector<int> arr(m + 1), dep(m + 1);
    for (int i = 1; i <= m; i++) cin >> arr[i];
    for (int i = 1; i <= m; i++) cin >> dep[i];

    // 按到达时间排序
    vector<pair<int, int>> flight;
    for (int i = 1; i <= m; i++) flight.push_back({arr[i], dep[i]});
    sort(flight.begin(), flight.end());

    // occupied: {离开时间, 廊桥编号}，按离开时间小根堆
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> occupied;
    // freeBridges: 空闲廊桥编号，小根堆（保证取最小编号）
    priority_queue<int, vector<int>, greater<int>> freeBridges;

    int nextBridge = 1;  // 下一个新廊桥的编号
    for (auto& f : flight) {
        int arrive = f.first, depart = f.second;
        // 释放所有已离开航班的廊桥
        while (!occupied.empty() && occupied.top().first <= arrive) {
            freeBridges.push(occupied.top().second);
            occupied.pop();
        }
        int bid;
        if (!freeBridges.empty()) {
            bid = freeBridges.top();  // 取最小编号的空闲廊桥
            freeBridges.pop();
        } else {
            bid = nextBridge++;       // 分配新廊桥
        }
        occupied.push({depart, bid});
        g[bid]++;  // 该廊桥服务数 +1
    }

    // 前缀和：g[k] = 前 k 个廊桥总共服务的航班数
    for (int i = 1; i <= m; i++)
        g[i] += g[i - 1];
}

int main() {
    freopen("airport.in", "r", stdin);
    freopen("airport.out", "w", stdout);
    ios::sync_with_stdio(false);
    cin.tie(0);

    cin >> n >> m1 >> m2;
    solve(m1, g1);
    solve(m2, g2);

    // 枚举国内分配 i 个，国际分配 n-i 个
    int ans = 0;
    for (int i = 0; i <= n; i++)
        ans = max(ans, g1[min(i, m1)] + g2[min(n - i, m2)]);

    cout << ans << endl;
    return 0;
}
```

**复杂度分析**：
- 排序：O(m log m)
- 优先队列模拟：O(m log m)
- 枚举分配：O(n)
- 总复杂度：O((m1 + m2) log(m1 + m2) + n)

**常见错误点**：
1. 忘记对航班按到达时间排序
2. 优先队列的离开时间比较写反（应释放 `depart ≤ arrive` 的廊桥）
3. `g[]` 数组没做前缀和
4. 当 i > m1 时 `g1[i]` 越界（需用 `min(i, m1)` 钳制）

### 例题2：[CSP-S 2022 T1] 假期计划

**题意概括**：给定 n 个景点（编号 1~n）和 m 条无向边（边权为 1）。小 Z 从 1 号景点出发，要选择两个不同的景点 A 和 B（A≠1, B≠1, A≠B），行程为 1→A→B→A→1，且每段路径的步数不超过 k。每个景点有一个权值，求 val[A] + val[B] 的最大值。

**数据范围**：n ≤ 2500，m ≤ 6200，k ≤ 2500。

**数据范围与部分分分析**：

| 数据范围 | 对应算法 | 预期分数 |
|---------|---------|---------|
| n ≤ 50 | O(n³) 枚举 + BFS | 20 分 |
| n ≤ 500 | O(n²) 枚举 + 每次BFS | 50 分 |
| n ≤ 2500 | 全源BFS + O(n²) 枚举 | 100 分 |

**算法选择**：

**思路一（暴力）**：枚举所有 (A, B) 对，每次 BFS 验证四段路径是否都 ≤ k。复杂度 O(n² × (n+m))，可得 50 分。

**思路二（正解）**：由于图是无权的，从每个节点 BFS 一次即可得到该节点到所有其他节点的最短路。预处理 `dist[u][v]` 后，枚举 (A, B) 只需 O(1) 查表判断合法性。

**AC 代码**：

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 2505;
const int INF = 0x3f3f3f3f;

int n, m, k;
long long val[MAXN];
vector<int> adj[MAXN];
int dist[MAXN][MAXN];  // dist[u][v]: u 到 v 的最短路

// 从节点 s 出发 BFS，计算到所有节点的最短路
void bfs(int s) {
    memset(dist[s], 0x3f, sizeof(dist[s]));
    dist[s][s] = 0;
    queue<int> q;
    q.push(s);
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        for (int v : adj[u]) {
            if (dist[s][v] > dist[s][u] + 1) {
                dist[s][v] = dist[s][u] + 1;
                q.push(v);
            }
        }
    }
}

int main() {
    freopen("holiday.in", "r", stdin);
    freopen("holiday.out", "w", stdout);
    ios::sync_with_stdio(false);
    cin.tie(0);

    cin >> n >> m >> k;
    for (int i = 2; i <= n; i++) cin >> val[i];

    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u);
    }

    // 全源 BFS：从每个节点出发求最短路
    for (int i = 1; i <= n; i++) bfs(i);

    // 枚举 A 和 B，找满足条件的最大 val[A] + val[B]
    long long ans = 0;
    for (int A = 2; A <= n; A++) {
        if (dist[1][A] > k) continue;       // 1→A 不超过 k 步
        for (int B = 2; B <= n; B++) {
            if (B == A) continue;            // A≠B
            if (dist[1][B] > k) continue;    // 1→B 不超过 k 步（即 A→1）
            if (dist[A][B] > k) continue;    // A→B 不超过 k 步
            ans = max(ans, val[A] + val[B]);
        }
    }

    cout << ans << endl;
    return 0;
}
```

**复杂度分析**：
- 全源 BFS：O(n × (n + m)) = O(2500 × 8700) ≈ 2.2×10^7
- 枚举 (A, B)：O(n²) = O(6.25×10^6)
- 总复杂度：约 2.8×10^7，1 秒内可完成

**常见错误点**：
1. 距离判断写成 `< k` 而非 `≤ k`（注意"不超过 k 步"的含义）
2. 忘记 A≠B 的约束
3. BFS 没有处理图不连通的情况（INF 比较）
4. val 数组没开 `long long`，权值之和溢出

!!! tip "优化进阶：O(n²) → O(n)"
    当 n 更大时（如 n ≤ 10^5），可以预处理每个节点的"可达且权值最大的前 3 个节点"。对于每个 A，只需检查这 3 个节点作为 B 是否与 A 不同，将枚举从 O(n²) 优化到 O(n)。

### 例题3：[CSP-S 2023 T1] 密码锁

**题意概括**：一个 5 位环形密码锁，每位数字 0~9。每次操作可选择起始位置 i 和长度 k（1≤k≤5），将位置 i 开始的连续 k 位（环形）同时 +1（mod 10）。给定 n 个目标状态，求从全 0 状态到所有目标状态的最少操作总次数。

**数据范围**：n ≤ 1000。

**数据范围与部分分分析**：

| 数据范围 | 对应算法 | 预期分数 |
|---------|---------|---------|
| n = 1 | 单次搜索/枚举 | 30 分 |
| n ≤ 100 | 逐个搜索 | 60 分 |
| n ≤ 1000 | BFS 预处理 + O(1) 查询 | 100 分 |

**算法选择**：

**思路一（暴力）**：对每个目标状态，DFS 搜索最少操作数。状态空间 10^5，但每次搜索开销大。

**思路二（正解）**：观察发现所有目标状态都从全 0 出发，操作可逆。从全 0 状态做一次 BFS，预处理到所有 10^5 个状态的最短距离，之后每个查询 O(1)。

**AC 代码**：

```cpp
#include <bits/stdc++.h>
using namespace std;

int dist[100005];  // dist[s]: 从 00000 到状态 s 的最少操作数

// 将 5 位数组编码为整数
int encode(int a[]) {
    int val = 0;
    for (int i = 0; i < 5; i++) val = val * 10 + a[i];
    return val;
}

// 将整数解码为 5 位数组
void decode(int val, int a[]) {
    for (int i = 4; i >= 0; i--) {
        a[i] = val % 10;
        val /= 10;
    }
}

int main() {
    freopen("lock.in", "r", stdin);
    freopen("lock.out", "w", stdout);

    // 从 00000 出发 BFS，预处理到所有状态的最短距离
    memset(dist, -1, sizeof(dist));
    queue<int> q;
    int start[5] = {0, 0, 0, 0, 0};
    int s0 = encode(start);
    dist[s0] = 0;
    q.push(s0);

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        int a[5];
        decode(u, a);
        // 枚举所有操作：起始位置 st，长度 len
        for (int st = 0; st < 5; st++) {
            for (int len = 1; len <= 5; len++) {
                int b[5];
                memcpy(b, a, sizeof(b));
                for (int j = 0; j < len; j++)
                    b[(st + j) % 5] = (b[(st + j) % 5] + 1) % 10;
                int v = encode(b);
                if (dist[v] == -1) {
                    dist[v] = dist[u] + 1;
                    q.push(v);
                }
            }
        }
    }

    // 读取 n 个目标状态，累加最少操作次数
    int n;
    long long ans = 0;
    cin >> n;
    for (int i = 0; i < n; i++) {
        int target[5];
        for (int j = 0; j < 5; j++) cin >> target[j];
        ans += dist[encode(target)];
    }

    cout << ans << endl;
    return 0;
}
```

**复杂度分析**：
- BFS 预处理：状态数 10^5，每个状态 25 条边 → O(2.5×10^6)
- 查询：O(n × 5) = O(5000)
- 总复杂度：O(2.5×10^6)，极快

**常见错误点**：
1. 忘记环形（位置 (st+j) 需要 `% 5`）
2. BFS 起点状态写错（应从 00000 开始）
3. 忘记 `+1 mod 10`（数字应为 0~9 循环）
4. 编码/解码函数写反

### 三道真题对比

| 维度 | 廊桥分配 (2021 T1) | 假期计划 (2022 T1) | 密码锁 (2023 T1) |
|------|-------------------|-------------------|-----------------|
| 算法类型 | 贪心 + 优先队列 | BFS + 枚举 | BFS 预处理 |
| 核心技巧 | 前缀和优化枚举 | 全源最短路 | 状态空间搜索 |
| 暴力分策略 | O(n×m) 模拟 | O(n²) 枚举+BFS | 逐个 DFS |
| 正解复杂度 | O(m log m) | O(n² + nm) | O(10^5 × 25) |
| 难度 | ★★ | ★★☆ | ★★ |

三道 T1 题的共同特点：**算法本身不难，但需要正确识别模型并仔细实现**。T1 的核心是"快"和"稳"——快速识别算法、稳定实现不出错。
